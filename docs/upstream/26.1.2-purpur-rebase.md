## Why Keila's own optimizations are not here yet

Keila's bespoke performance stack was the **Leaf** patch set, rebranded
`org.dreeam.leaf` → `gg.tame.keila`. It targets Minecraft **1.21.11**; Purpur is
on **26.1.2** (several drops later) and even Leaf upstream has not ported to
26.1.2. Re-applying it is a real port, not a copy:

- paperweight applies feature patches with strict **`git am --3way`** — no fuzzy
  matching. A 1.21.11 patch whose context doesn't byte-match the 26.1.2 file
  cannot apply. **Proven on CI**: the build applied Paper's 927 + Purpur's 233
  source patches + all 21 Purpur feature patches, then the first re-ported Keila
  patch failed with `could not build fake ancestor`.
- Fixing patch context requires reading the **decompiled 26.1.2 source**, which
  only exists inside a build. The authoring sandbox can't reach
  `repo.papermc.io` / `piston-meta.mojang.com` (egress-blocked), so the re-port
  **must be done in a build-capable, Java 25 environment** (e.g. CI runners or a
  session whose network policy allows those hosts).

## Prerequisites the source depends on

The Keila source is one tightly-coupled unit. Even the simplest feature pulls in:

- the **config framework** (`gg.tame.keila.config.*` + all `config/modules/*`),
- the **feature catalog** (`gg.tame.keila.feature.*`),
- **Gale**: `org.galemc.gale.version.AbstractPaperVersionFetcher`
  (`KeilaVersionFetcher` extends it) — needs Gale's version-fetcher patch,
- **Moonrise**: `ca.spottedleaf.moonrise.common.time.TickData`,
- Paper API `io.papermc.paper.ServerBuildInfo`,
- a custom `CraftDefaultPermissions.KEILA_ROOT` (added by the commands patch).

So a partial port does not compile — the framework + these prerequisites must
land together before any feature source compiles.

## Re-port procedure (build-capable env)

1. Vendor the Gale/Moonrise prerequisite patches the source needs (version
   fetcher, `TickData`), or stub the few symbols.
2. Re-port in dependency order, smallest foundation first: rebrand →
   `CraftDefaultPermissions.KEILA_ROOT` → config framework → command suite →
   then the optimization patches. Apply each, resolve the `git am` conflict
   against the live decompiled 26.1.2 source, `./gradlew applyAllPatches` to
   validate, repeat.
3. Drop any patch now superseded by Purpur or upstreamed into Paper (Purpur and
   Leaf overlap functionally — expect many to be redundant or to conflict).
4. Re-add `build-data/keila.at` (fork-named so paperweight auto-loads it) from
   the 38 entries in `leaf.at`, reconciled to 26.1.2 mappings.
5. Honor `docs/upstream/patch-risk-index.md`: P0/P1 async patches need metrics,
   rollback notes, and soak tests per `docs/upstream/sync-policy.md`.
6. `./gradlew build` green, then verify a runnable jar.
