# Keila -> Purpur 26.1.2 Re-base Runbook

Status: **Purpur base adopted on this branch.** Keila now forks Paper directly and
vendors **Purpur `ver/26.1.2`**'s patch set in place of the old Leaf stack. CI
(which can reach PaperMC/Mojang) is the build validator; this Java-21, no-egress
authoring sandbox cannot run paperweight, so the green build is proven on CI.

## What changed (this branch)

- **Dropped Leaf entirely:** removed `leaf-api/`, `leaf-server/`,
  `leaf-archived-patches/`, and `build-data/leaf.at`. This also removed Keila's
  own 180 source files (`gg.tame.keila.async.*`, the `/keila` command suite) and
  3 Keila patches, which were written against the Leaf tree — they are **re-layered
  in a follow-up phase** (see Recovery below).
- **Vendored Purpur `ver/26.1.2`** (HEAD `bb69e152573a7d7d86966257a30050144029a523`):
  - `purpur-api/` and `purpur-server/` copied verbatim (build.gradle.kts patches,
    `paper-patches`, `minecraft-patches`, and Purpur's own `src/`).
  - `build-data/purpur.at` + `build-data/dev-imports.txt`. paperweight loads the
    access-transformer file by fork name, and Purpur's server patch registers the
    `purpur` fork — so `purpur.at` wires up automatically.
  - **346 active patches**, all authored against this exact Paper base, so they
    apply as-is.
- **Build config rewired to Purpur's:** root `build.gradle.kts` and
  `settings.gradle.kts` now reference `purpur-api`/`purpur-server`;
  paperweight-patcher bumped **`2.0.0-beta.19` -> `2.0.0-beta.21`** (Purpur's
  version, required for its patch format); `--enable-preview` dropped (Purpur does
  not use it on this base); `jitpack` repo added. Keila identity is preserved at
  the distribution layer: `group=gg.tame.keila`, `rootProject.name=keila`,
  publishing to `maven.tame.gg`.
- **No `mache`/`paperclip` pin:** Purpur's server patch does not override them, so
  Keila inherits Paper 26.1.2's own `mache` automatically. The old
  `mache:1.21.11+build.1` mismatch is gone.
- Scripts updated `leaf-* -> purpur-*` paths.

## Recovery: Keila's own feature work

Keila's bespoke source and patches are preserved in git history at the commit
**prior to this rebase** (the last Leaf-based commit on this branch). To re-layer:

- Source (180 files): `leaf-server/src/main/java/gg/tame/keila/**`
  (`async/`, `command/`, `config/`) and any `leaf-api/src/.../gg/tame/keila/**`.
- Keila patches: `0328-Keila-branded-console-chat-logs.patch`,
  `0329-Keila-startup-experience.patch` (server), `0080-Keila-identity-rebrand.patch`
  (api).

Recover with e.g. `git show <pre-rebase-commit>:<path>` or
`git checkout <pre-rebase-commit> -- leaf-server/src/main/java/gg/tame/keila`.

## Re-layer phase (follow-up)

1. Move Keila's `gg.tame.keila` source into `purpur-server/src/main/java/`
   (and api equivalents), adjust to 26.1.2 internals, compile in the build env.
2. Re-create the async/command hooks as Keila `minecraft-patches`/`paper-patches`
   on top of Purpur's queue (respecting `docs/upstream/patch-risk-index.md` —
   async work is P0/P1: needs metrics, rollback notes, soak tests).
3. Re-apply the Keila identity/console/startup patches.

## Build + verify (capable env / CI only)

```
./gradlew applyAllPatches --stacktrace
./gradlew check
./gradlew createMojmapPaperclipJar
```

Needs egress to `repo.papermc.io` (mache/dev-bundle) and `piston-meta.mojang.com`
(vanilla jar) plus a Java 25 toolchain. The authoring sandbox has neither (those
hosts return `host_not_allowed`, local JDK is 21); GitHub Actions runners do, so
CI on the PR is the source of truth for the green build.
