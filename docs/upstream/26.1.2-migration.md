# Keila 26.1.2 Platform Migration Runbook

Status: **planned / blocked on build environment.** This captures the verified
upstream coordinates and the full scope of moving Keila from the Minecraft
`1.21.11` base to the **real** `26.1.2` platform. It is not a label change (see
`docs/keila/identity.md` for the decoupled-label interim that ships today); it is
a full upstream version bump plus patch reconciliation.

## Why this is a major bump, not a patch-apply

Keila forks **Leaf** (`Winds-Studio/Leaf`), and its ~425 patches are Leaf's
stack plus a few Keila patches. As of this writing **Leaf is still on `1.21.11`**
(`mcVersion=1.21.11`, pinned to the same Paper commit Keila uses). Paper has
moved to `26.1.2`. So a proper Keila 26.1.2 means re-doing Leaf's entire
`1.21.11 -> 26.1.2` port against a new Minecraft drop, then layering Keila's
patches on top. The Paper/Bukkit half is pulled in automatically by pointing
`paperCommit` at Paper `main`; the Leaf/Keila half is the real labor.

`26.1.2` is a genuine Minecraft version under Mojang's 2026 `year.drop.hotfix`
scheme (the `26.1` "Tiny Takeover" drop, hotfix 2).

confirms the Paper `76d2ac7` base is production-shipped, not just a dev branch.

## Toolchain changes Paper made between 1.21.11 and 26.1.2

These hit the build files and CI, independent of the per-patch work:

- **Java 21 -> Java 25** for compilation (`JavaLanguageVersion.of(25)`,
  `options.release = 25`) and the run task. Keila currently pins Java 21
  everywhere (`build.gradle.kts`, subprojects, CI `setup-java`, `.java-version`,
  README) and uses Java-21 `--enable-preview` patterns that must be revisited.
- **Spigot mappings + reobf removed**: the `spigot { … }` block and
  `reobfPackagesToFix` are gone from `paper-server/build.gradle.kts`.
- **Plugin-remap machinery removed**: `srgutils`, `AutoRenamingTool`, and the
  `io.papermc:reflection-rewriter*` dependencies are gone.
- Dependency bumps: `io.papermc.fill.gradle` 1.0.10 -> 1.0.11,
  `ca.spottedleaf:concurrentutil` 0.0.8 -> 0.0.10, log4j 2.24.1 -> 2.25.2,
  junit 5.12.2 -> 6.0.3, mockito 5.14.1 -> 5.22.0, classgraph 4.8.179 -> 4.8.184.

## Migration procedure

1. **Build config** (`gradle.properties`): set `mcVersion`/`apiVersion=26.1.2`,
   `version=26.1.2-R0.1-SNAPSHOT`, `paperCommit=76d2ac7…`. Remove the
   decoupled-label scaffolding (`keilaVersion`, the manifest override, the
   README "Upstream build base" row) — on a real bump the base *is* 26.1.2.
2. **Java 25**: bump every Java 21 reference (root + subproject toolchains,
   `options.release`, CI `setup-java` to 25, `.java-version`, README) and audit
   the `--enable-preview` usages.
3. **Single-file patches**: rebase `leaf-server/build.gradle.kts.patch` and
   `leaf-api/build.gradle.kts.patch` against Paper `main` (mache/paperclip
   bumps, removed spigot/reobf/reflection-rewriter, dep bumps). Regenerate the
   committed output `build.gradle.kts` files. Easiest via `diff -u` of the new
   Paper base vs. the Keila-customised file.
4. **`./gradlew applyAllPatches`**: reconcile the ~425 `leaf-server/`
   minecraft-patches + paper-patches (and `leaf-api/paper-patches`) against the
   decompiled 26.1.2 source. Expect a large fraction to reject; fix each against
   the new vanilla code. Drop patches Paper/Leaf have since upstreamed.
5. **Risk gate**: every P0/P1 patch in `docs/upstream/patch-risk-index.md`
   (parallel world ticking, entity-tracker threading, chunk sync, player-data
   save, packet ordering, mob AI/spawning) needs re-validation, stress + soak
   tests, and rollback notes per `docs/upstream/sync-policy.md` before shipping.
6. **Build + verify**: `./gradlew check createMojmapPaperclipJar`, then the
   `scripts/verifyLocal.sh` flow.
7. **Docs**: README Minecraft target stays `26.1.2`; update Java runtime to 25;
   refresh `scripts/upstreamCommit.sh` compare refs (Paper 26.1.2 lives on
   `main`).

## Environment requirements

The reconciliation cannot be done blind — it needs the decompiled 26.1.2 source,
which requires a paperweight run. That run needs:

- Network egress to `repo.papermc.io` (mache) and `piston-meta.mojang.com`
  (vanilla jar). **Both are blocked (HTTP 403) in the Claude Code web session
  used to author this runbook; GitHub is reachable.** Keila's GitHub Actions
  runners do have access (CI builds the 1.21.11 base today).
- A **Java 25** JDK (the authoring session only has JDK 21).

## Recommendation

Either (a) run this procedure in a network-capable, Java 25 environment with
paperweight able to decompile 26.1.2, or (b) wait for `Winds-Studio/Leaf` to
publish a `26.1.2` branch and then rebase only Keila's own patches on top — far
smaller and the normal downstream path. Until then, the shippable artifact is
the decoupled "Keila 26.1.2 on the stable 1.21.11 base" already on PR #7.
